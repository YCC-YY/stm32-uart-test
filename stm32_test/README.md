     # 嵌入式串口自动化测试框架
     > 一个基于 Python + pytest + STM32 的嵌入式设备自动化测试框架，实现固件与上位机串口命令交互自动化验证。

     ---
     ## 📋 项目简介
     本项目面向嵌入式设备软硬件协同验证场景，解决传统手工测试效率低、回归测试成本高的痛点。
     本项目完成硬件通信层与测试用例层解耦，搭建可复用的板级自动化测试原型，可快速扩展适配其他嵌入式外设的功能回归验证。

     被测对象：基于 STM32F103 的串口命令控制系统，支持 LED 开关控制、命令应答、非法指令处理。

     > 设计目标：接入CI/CD流水线，代码提交触发自动化测试，将缺陷发现时机前移。

     核心价值：
     - 将手工回归测试操作，压缩至数十秒自动化脚本执行
     - 测试用例与串口通信框架解耦，新增被测功能无需修改底层通信代码
     - 探索硬件在环HIL测试方案，为真实嵌入式设备自动化测试提供原型参考

     ---

     ## 🚀 快速开始
     ### 环境要求
     | 依赖 | 版本 |
     |------|------|
     | Python | 3.8+ |
     | STM32 开发板 | STM32F103 系列 |
     | 操作系统 | Windows / Linux |

     ### 安装依赖
     ​```bash
     pip install -r requirements.txt
     ```

     > requirements.txt主要依赖：`pytest pyserial pytest‑html`

     ### 修改串口配置
     编辑 `test_cases/test_led.py` 内部串口号、波特率，与硬件实际COM口保持一致。

     ### 运行测试
     ```bash
     # 执行全部测试用例
     pytest test_cases/ -v

     # 生成 HTML 测试报告
     pytest test_cases/ -v --html=report.html --self-contained-html
     ```

     ## 📊 测试覆盖矩阵
     | 测试类别 | 测试用例         | 预期结果                  | 覆盖点             |
     | -------- | ---------------- | ------------------------- | ------------------ |
     | 功能测试 | led_on           | 返回 -->LED 打开          | 正常命令响应       |
     | 功能测试 | led_off          | 返回 -->LED 关闭          | 正常命令响应       |
     | 功能测试 | hello            | 返回 -->Hello from STM32! | 正常命令响应       |
     | 异常测试 | random_str       | 返回 -->未知命令          | 非法命令容错处理   |
     | 边界测试 | 超长字符串       | 返回 -->未知命令          | 接收缓冲区边界保护 |
     | 压力测试 | 循环连续下发命令 | 全部正确应答              | 串口通信稳定性     |

     ## 🔄 CI/CD流水线说明
     > ⚠️ **注意：普通GitHub Actions云服务器没有物理串口、没有STM32硬件，无法直接运行硬件在环测试。**

     企业真实落地方案：
     1. 使用**自托管Runner**，将STM32开发板接在本地服务器/PC；
     2. GitHub代码push触发，调度本地Runner执行pytest硬件测试；
     3. 测试完成上传HTML测试报告作为产物。

     本项目已经完成原型验证，`.github/workflows` 为待扩展模块。
